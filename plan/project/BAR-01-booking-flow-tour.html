BAR-01 · Booking flow tour · post-refactor

One booking, one lifecycle, N rooms.

A guest books 2 rooms. The system creates one booking doc, not two. The admin sees one dashboard card, not two. The verify action clears both rooms in one click. This is the long-term shape after BAR-01 lands.

4. Server creates 1 booking doc. Guest pays via GCash. Email fires.

    What the desk has to know today

    "A booking can be part of a reservation with multiple rooms. Verify affects all rooms in the reservation that are covered by the amount. Reject affects all rooms. Cancel can be this room or all rooms. Discount can be this room or all rooms. Reschedule moves the date for one room. Add room adds to the reservation."
