**The audit found a class of defect the handoff did not list at all.** The read-after-write 500s were a **live, money-affecting S1** — the guest's own self-service cancel could fail, and a cancellation that half-applied would not release a voucher use or claw back points. It is now fixed, deployed and proved in both directions. It is also why this backlog now carries a **server typecheck gate**: the fix that closed it had two compile errors that the old test setup could not see.

**And the audit found a defect in its OWN work.** The F-D3 fix (the ledger pass in the finance scanner) broke the **admin app's build**, so the production admin app silently stayed on v2.21.9 while the guest app moved to v2.21.16 — the admin was missing the kitchen-list fix, the store-report CSV export and the F-A6 instruction fix the whole time. The lesson is the same shape as the read-after-write one: **a local build passing is not the same as a deployed build passing**, because the deployed build installs a different set of packages. That is why this backlog now carries a second gate — `npm run check:app-closure` — which asks TypeScript for the exact program each app would compile and fails when it reaches a package the app does not declare.

The two closed items that were **live money-permission holes** (SEC-3, SEC-4) are the important ones: both are now enforced **on the server**, proven with a real front-desk token (HTTP 403) and a real admin token (reaching validation).

**What is still open is now DATA and CONFIGURATION, not reporting.** F-A4 and F-D4 are QA-fixture arithmetic; F-A6 is a corrected UI path; NO-ID-A67 is a room-type configuration the owner chooses; RPT-2 names a setting that does not exist in the codebase and needs the owner's clarification.

### The structural fix — a scope reconciliation gate

The two lists must be diffed **before** a report is allowed to close as "no findings remain open". The report ships with `scripts/qa/verify-matrix.ts`, which already checks its OWN catalogue against its OWN matrix. What it does **not** do is check the sibling backlog's ids. A check that reads `HANDOFF-2026-10-23.md` §6's id column and fails when an id is absent from the report — unless it is explicitly marked out-of-scope with a reason — is the difference between "no findings remain open" meaning what it appears to mean.
